## 5. Lancer le faux serveur et les tests

Le faux serveur (`scripts/fake-supabase.mjs`) exécute les vraies migrations sur PGlite et applique les vraies RLS. Il gère l'authentification, les appels `rpc` et les lectures/écritures PostgREST courantes ; **il ne gère pas** les ressources imbriquées, le temps réel, le stockage ni les e-mails (en-tête du script).

À la main, pour développer :

```bash
node scripts/fake-supabase.mjs --port 54321          # base en mémoire ; --data <dossier> pour la garder
# .env.local (jamais commité) :
#   NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
#   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=local-fake-key
npm run dev                                           # http://localhost:3000
```

Les variables `NEXT_PUBLIC_*` sont figées au moment du `build` : après les avoir changées, reconstruire.

| Commande                     | Ce qu'elle fait                                                                                                                                                                         |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run check`              | lint, types, format, Vitest, RLS, build : à lancer avant chaque PR                                                                                                                      |
| `npm run test`               | Vitest (tests à côté du code, `*.test.ts`)                                                                                                                                              |
| `npm run test:db`            | migrations et RLS sur PGlite (`scripts/test-rls.mjs`)                                                                                                                                   |
| `npm run test:e2e`           | Playwright **sans comptes** : pages publiques et redirections ; les scénarios connectés sont ignorés (port 3100)                                                                        |
| `npm run test:e2e:connected` | Playwright **avec comptes** : démarre lui-même le faux serveur (port 54399, option `--test-clock`) et l'application (port 3101), puis joue tous les tests ; un seul navigateur (bureau) |

`playwright.connected.config.ts` positionne `E2E_CONNECTED=1` ; les specs connectées se désactivent sans cette variable. Pour tester une séance longue sans attendre, le test appelle `POST /__test/advance-clock` (avec `--test-clock`), en passant le `username` pour ne déplacer que la séance de ce compte (les tests tournent en parallèle sur un seul serveur) ; l'application ne contient aucun code de test. `e2e/support/new-account.ts` crée un compte avec pseudo. Détails : `docs/E2E.md`. Démo sur un vrai projet : `docs/DEMO.md` et `scripts/seed-demo.mjs`.

Specs (`e2e/`) : parcours à deux comptes (`journey-connected`, `demo-journey`), `onboarding`, `first-run`, `shell`, `apercu`, `design-system`, `focus-immersive`, `invite`, `reminders`, `privacy`, `nav-links`, `stats-charts`, `landing`, `smoke`, `settings`, et des specs par écran (`achievements` et `leaderboard`, avec un cas connecté chacun ; `friend-profile` et `stats`, anonymes) ; ceux de Stan : `academic`, `agenda`, `planning`, `account`, `username`.

## 7. Rappels de sécurité propres à ces écrans

- Les notes (`grades`) et matières (`subjects`) ne sont jamais visibles par un autre utilisateur (décision D-16).
- L'XP n'est jamais écrite par le client : elle l'est par `finish_study_session`.
- Les horodatages des séances sont écrits par la base uniquement (décision D-17).
- Toute nouvelle table : RLS, policies `to authenticated`, cas dans `scripts/test-rls.mjs`.
- Aucun secret dans le dépôt ; seule la clé _publishable_ peut être exposée (`NEXT_PUBLIC_…`).
- Anti-pression (design Revio) : un seul encouragement par jour et par ami, aucun compteur public de kudos ou de likes, aucune notification entre 21 h et 8 h (cette dernière règle reste à appliquer côté serveur quand les rappels existeront).
